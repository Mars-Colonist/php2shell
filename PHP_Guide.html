PHP2Shell Anatomy & Local Lab Setup

Comprehensive reference for understanding runtime-level vulnerabilities and configuring an isolated sandbox environment.

1. Vulnerability Overview & Scope

Unlike application-layer issues (such as SQLi or XSS found in traditional labs like Mutillidae), PHP2Shell is a core memory-corruption flaw residing within the C source code of the PHP interpreter itself.

Target Endpoints

Any valid PHP endpoint (e.g., /index.php, /test.php) can trigger the bug because request handling happens during core HTTP parsing before application logic executes.

Vulnerable Versions

All versions from PHP 5.4 up to 8.5.11. Patches are available in PHP 8.5.12, 8.4.27, 8.3.36, and 8.2.35.

2. Rapid Docker Lab Deployment

To evaluate proof-of-concept scripts safely, spin up a pre-patch vulnerable container locally using the official PHP Apache images:

docker run -d --name php2shell-lab -p 8080:80 php:8.4.26-apache

Command Breakdown:

  • -d: Runs the container in background (detached) mode.
  • --name php2shell-lab: Assigns an easy reference tag to the container.
  • -p 8080:80: Maps host port 8080 to container port 80 (http://localhost:8080).
  • php:8.4.26-apache: Pulls a target unpatched version immediately prior to security advisories.

3. Verification & Teardown Checklist

1
Verify Runtime Version: docker exec -it php2shell-lab php -v
2
Ensure Network Isolation:

Confirm the container is bound strictly to localhost and firewalled from public exposure.

3
Cleanup Lab: docker stop php2shell-lab && docker rm php2shell-lab
